# Operation Steel Tide v1.3.5

This hotfix restores macOS-to-Windows LAN joining when the Mac can discover a room but the ENet connection times out.

## LAN Connection Fixes

- The macOS app now declares `NSLocalNetworkUsageDescription` in its packaged `Info.plist`.
- Opening the LAN room browser sends a minimal permission probe so macOS requests Local Network access before the player attempts to join.
- Connection failure text now points to Local Network permission and host UDP `28960` access.
- The real host/client diagnostic accepts an isolated endpoint and waits for an actual connection instead of relying on a fixed startup delay.
- LAN troubleshooting documentation now covers the macOS Local Network toggle and Windows active-profile firewall access.

On macOS, accept the Local Network prompt. If permission was previously denied, enable Operation Steel Tide under **System Settings > Privacy & Security > Local Network**, quit the game completely, and reopen it.

## Verification

The project and Windows release pipeline build with zero warnings and zero errors. The following Godot diagnostics pass: `--validate-lan-discovery`, `--validate-network-endpoint`, `--validate-operations-office`, `--validate-demolition-briefing`, `--validate-demolition`, and `--validate-squad`.

A real two-process ENet host/client pair also passes connection establishment, remote human replacement, shot relay, ability relay, and cooldown gating on an isolated diagnostic port. The final macOS package was inspected to confirm version `1.3.5` and the `NSLocalNetworkUsageDescription` key inside the application bundle.
